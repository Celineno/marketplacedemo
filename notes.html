Project notes

How this marketplace works

What we built and who it's for

This is a second-hand marketplace demo for the general public, letting people browse local listings, search using natural language, and ask questions about the catalogue instead of manually scrolling through every item. It includes a browse grid, a detail view for each listing, natural-language semantic search, an AI-powered Q&A assistant, filtering/sorting, and the ability for anyone to add a new listing.

What's seeded, simulated, or limited

The 26 seeded listings use fixed real image URLs; new listings added through the "Add a listing" form also use user-provided image URLs.

New listings are stored in memory only (not a real database), so they reset if the server restarts.

No real user accounts, authentication, or payment processing, and there is no messaging or contact system between buyers and sellers.

AI tools and models used

Codex CLI (via a class-provided gateway) was used to build the site.

Natural-language search uses the text-embedding-3-small embeddings model, combined with a category-tag boost for precision on common terms.

Catalogue Q&A uses the gpt-5.6-terra chat model, grounded in the full current catalogue, instructed to answer only from provided data and acknowledge when something isn't available.

What we chose not to build, and why

A real database and persistent listing storage were scoped out in favor of in-memory storage, since seeded/simulated data is an accepted approach for this demo and avoids deployment complexity.

Postal-code-based proximity search was considered but scoped out in favor of a simpler location/category filter.

Real payments, logistics, and authentication were intentionally left out, as the assignment scope focuses on marketplace browsing and AI features.

Known issues and unfinished parts

New listings and their categories are not persisted; they reset on server restart.

No automated tests were run; all functionality was manually verified through the browser during development.

Inconsistency with presenting the results of the Ask for: Single items/ Multiple Items

Search results are precise when a query matches an existing category (e.g. "gaming," "kitchen" return only items in that category). For descriptive or ambiguous queries that don't match a category (e.g. "desk," "room"), results fall back to pure semantic similarity, which can include loosely related items alongside strong matches, since embedding similarity scores for genuinely relevant and irrelevant items can be close for broad terms.
